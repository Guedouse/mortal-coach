# 常见问题（Q&A）

> 先看报错里的**阶段名**。程序每次失败都会写「失败（阶段 XXX）：…」，这个阶段名就是下面表格的第一列。
> 完整过程在 `library/logs/<标签>.log`（标签就是那一局的编号，例如 `261118C`）。

---

## 0. 三十秒定位

| 你看到的 | 大概是 |
|---|---|
| 阶段 `NO_TOKEN` | 浏览器过不了人机验证（网络 / 代理 / 需要手动点） |
| 阶段 `REPORT_DOWNLOAD_FAILED`，带 `WinError 10061` | 连接被拒绝：可能是没在运行的本地代理，也可能是目标/网络/安全软件（看日志里的代理与目标地址） |
| 阶段 `SUBMIT_REJECTED` | Mortal 服务端拒绝了这份牌谱（多为偶发，重试即可） |
| 阶段 `SUBMIT_TIMEOUT` / `REPORT_TIMEOUT` | Mortal 排队太慢或牌桌没渲染完 |
| 阶段 `NO_REPORT_URL` | 提交后没进到报告页（链接失效 / 验证过期 / 官网改版） |
| 阶段 `ENV_INCOMPLETE` | 包内运行时缺失，或设置里填的路径不对 |
| 阶段 `CHROME_UNAVAILABLE` | 找不到可用的 Chromium 浏览器 |
| 阶段 `INPUT_INVALID` | 链接 / 对局 ID 不对，或缺座次 |

日志里这几行最有用：`NET_INFO proxy=…`（走没走代理）、`SUBMIT_URL …`（真正提交的地址）、
`PAGE_STATE {…}` / `NO_TOKEN_STATE {…}`（验证卡在哪一环）、`TOKEN_OK len=…`（拿到 token 了）。

## 1. 阶段 `NO_TOKEN`：人机验证没拿到 token

这是最常见的一个。按日志里的 `PAGE_STATE` / `NO_TOKEN_STATE` 分三种，处理方式完全不同：

| 日志状态 | 含义 | 怎么办 |
|---|---|---|
| `form: false` | 浏览器里 **Mortal 首页都没打开** | 这台机器到 `mjai.ekyu.moe` 不通。先在浏览器里手动打开它；打不开就是网络 / 代理 / 防火墙问题。 |
| `cf: false` | 首页开了，但 **`challenges.cloudflare.com` 的脚本加载不出来** | 连不上 Cloudflare。换网络，或把代理开对（系统代理、而不是只设环境变量）。 |
| 三个都 true 却没 token | Cloudflare **要求人工确认** | 设置里勾「显示浏览器窗口」再点「分析」：窗口会自己开到屏幕正面，界面同时显示「等待你在浏览器里完成人机验证」。看到「确认您是真人」点一下即可，点完自动继续。**程序不会替你点**（点不准会把挑战卡在「正在验证…」），也不会在等待期间刷新页面。 |

如果等了一段时间还没点，界面会变成可恢复状态：浏览器**不会关**，页面还在，点「继续等待」接着等、点「显示验证窗口」把窗口再提到前面、点「取消这次」才关掉。设置页还有一个「打开验证页面」按钮，可以先单独确认浏览器和网络是否可用，不必真的提交一局。

其他已知原因：

- **换机器后第一次**：实例目录 `chrome-profile` 里的 cookie 是旧机器的 DPAPI 加密的，新机器解不开。新版会按注册表 `MachineGuid` 认出来，自动改名 `chrome-profile.old` 并重建——你不用手删。老版本请手动删掉该目录。
- **删过 `chrome-profile`**：等于新浏览器，需要重新过一次验证，正常。
- **换了网络 / 出口 IP**：Cloudflare 风控会提高，可能又要人工点一次。
- **用的哪个浏览器**：默认用系统正式版 Chrome / Edge；只有系统里一个都没有时，才退回 full 包内的 Chromium 快照。设置页「提交用的浏览器」下面会显示**实际使用的浏览器与版本**，出问题时先看这一行。
- **`full` 包升级后换了内核**：以前包内 Chromium 排在系统浏览器前面，会让同一个 profile 突然变成「新浏览器」。现在顺序反过来了；如果之前一直用包内那份，可以在设置里手动指到它的 exe。
- **第一次用就要求验证是正常的**：应用用的是**自己独立的浏览器资料目录**，不会继承你日常 Chrome / Edge 里的登录与验证状态（刻意的：不碰你的日常 Cookie）。所以第一次使用、换了程序目录、或手动删过 `chrome-profile`，网站要求点一次验证都属于正常。
- **验证能管多久**：通过后网站会在资料目录里留一枚通行证（`cf_clearance`）。只要**同一个浏览器 + 同一个出口 IP**，后续分析通常不再要你点。但它不是永久的，应用也不承诺「点一次永远免验证」——换网络 / 开关加速器、浏览器大版本升级、资料目录重建，都可能让网站重新要求确认。另外每次提交用的验证响应本身只对这一次有效（Cloudflare 单次 300 秒），所以不能把一次响应拿去复用给别的牌谱。

## 2. 阶段 `REPORT_DOWNLOAD_FAILED`：`WinError 10061`

**现象**：牌谱明明提交成功了，取报告时却报「由于目标计算机积极拒绝，无法连接」。

**原因**：`10061` 是「连接被拒绝」——通常是本机端口没人监听，但**不一定就是本机代理**：
目标站点拒绝、中间网络或安全软件拦了连接，也会给出同样的错误。

最常见的一种：环境变量或系统设置里留着 `HTTP_PROXY` / `HTTPS_PROXY=http://127.0.0.1:xxxx`，
那个代理软件却没开。这里有个关键点：**Chrome 不读这两个环境变量**，所以会出现
「浏览器能提交、Python 下载不了」这种看起来矛盾的现象。

**怎么判断是哪一种**：错误信息里会打印**实际使用的代理**和**目标地址**。
代理一栏不是空的、而那个端口确实没程序在听 → 就是本机代理的问题；
代理为空或本来就是直连却仍然被拒 → 往目标站点、网络、安全软件方向查。

**三种解法（任选）**：

1. 用新版（已修）：下载失败会自动改直连重试一次，多数情况直接通过。
2. 把代理软件打开——如果这台机器确实需要代理才能上外网，这才是正确做法。
3. 清掉环境变量：`set HTTP_PROXY=` / `set HTTPS_PROXY=` 后重启程序，或去「系统属性 → 环境变量」删掉。

自查：cmd 里 `echo %HTTPS_PROXY%`，打出一串 `http://127.0.0.1:xxxx` 而对应软件没运行，就是它。

错误码对照：

| 错误 | 含义 |
|---|---|
| `10061` | 连接被拒绝：代理没开 / 端口不对 |
| `10060` | 超时：需要代理但没配，或线路太慢 |
| `11001` | 域名解析失败：DNS / hosts / 断网 |
| `CERTIFICATE_VERIFY_FAILED` | 证书校验失败：有中间人代理在拦 HTTPS |

## 3. 阶段 `SUBMIT_REJECTED`：「Mortal 拒绝了这个牌谱」

多数是 **Mortal 服务端偶发抓取失败**——同一个链接在网页版手动提交往往能过。程序已自动重试 3 轮
（每轮都会用 `?retry=<时间戳>` 重新导航，避免复用上一轮的 Turnstile token），仍失败就隔几分钟再点一次「分析」。

排查顺序：

1. 把链接贴到浏览器里手动打开，确认牌谱本身能看（不是私密 / 已删除 / 需要登录）。
2. 确认是**牌谱页**而不是对局结果页；Mortal 只认完整牌谱。
3. 一番街 / 姬麻将要对局 ID，贴成链接会失败。
4. 还是不行就看日志最后几行 `SUBMIT_URL`，确认提交的地址是不是你想要的。

---

## 4. 阶段 `SUBMIT_TIMEOUT` / `REPORT_TIMEOUT`

- `SUBMIT_TIMEOUT`：整轮超过 20 分钟。Mortal 排队久的时候会这样，晚点再试。
- `REPORT_TIMEOUT`：报告页打开了但牌桌一直没渲染完。通常是对方服务器慢，等几分钟重试。

程序不会再像旧版那样傻等 9 分钟——连续 3 轮还停在首页会立刻以 `SUBMIT_NOT_SENT` 返回。

---

## 5. 阶段 `ENV_INCOMPLETE` / `CHROME_UNAVAILABLE`

- `ENV_INCOMPLETE`：包内 `runtime\python\python.exe` 或 `runtime\node\node.exe` 不在。
  发行包不该出现；源码运行时要自己装，或在设置里指定。
  `mortal-coach.exe --selftest` 会打印 app / library / config / python / node / chrome / problems 七项，一眼看出缺什么。
- `CHROME_UNAVAILABLE`：没找到 Chromium 浏览器。lite 版装 Chrome 或 Edge，或
  在设置里手动指到 exe；full 版自带 Chromium，出现这个说明 `runtime\chromium\` 被删了。
  注意别指到日常正在运行的实例——程序必须用独立 profile 起新实例才能开调试端口。

---

## 6. 分析很慢 / 一直排队

- 正常单局 1~5 分钟，Mortal 排队久时更慢。进度条上的阶段会告诉你卡在哪。
- 批量导入多局时不要并发点，程序是串行的。
- 想只补缺的解读、不重新提交 Mortal：双击 `一键重建解读.bat`（本地算，不联网）。

## 6.1 提示「牌谱库正被另一个 Mortal Coach 使用」

同一个库同一时刻只允许**一个**窗口写，否则两边的 `bad_moves.json` 和 `coach/index.json`
会互相覆盖。读到这句提示时按场景处理：

| 场景 | 表现 | 处理 |
|---|---|---|
| 开了两个窗口，指向同一个库 | 后启动的那个只能浏览，分析/删除被拒 | 关掉一个窗口；或把其中一个的库改到别处 |
| 在设置里切到一个正被占用的库 | 提示「正被另一个 Mortal Coach 使用」，**配置不改、库也不切** | 先关掉占用的窗口，再切 |
| 双击 `一键重建解读.bat` / `rebuild.bat` | 打印被占用的库，**退出码 3**，一个文件都不写 | 关掉窗口再双击 |
| 库放在只读位置（光盘、只读共享） | 启动时提示「建不出锁文件」，只能浏览 | 把库换到可写目录 |

判断依据是库目录下的 `.mc-lock` 文件被谁锁着。**文件本身留着是正常的**，不用删；
进程正常退出或崩溃时，系统会自动释放它。实在怀疑卡住了，看一下任务管理器里还有没有
`mortal-coach.exe`。

命令行/脚本里判断结果：`rebuild_all.py` 返回 **3** 表示库不可写（1 表示库不存在或这轮有局重建失败）。

## 7. 历史牌谱是空的 / 日期下拉没选项

| 现象 | 原因 | 处理 |
|---|---|---|
| 历史空、但库里有数据 | 牌谱库指到了别的目录 | 设置里核对路径与统计数字（`几局 · 几份报告…`）。 |
| 只有「全部年份」可选 | 该库确实没有 `coach/*.json` | 分析一局，或把旧的 `library` 拷进来。 |
| 年月日选不到某项 | 设计如此 | 只列真的有牌谱的项；没牌谱的月和日不会出现。 |

## 8. 中间那栏的权重表是空的

权重表的数据来自 Mortal 报告里「这一巡的候选评分」。以下情况没有数据：

- 这一巡**不是你的决策点**（别家摸打、结算），右侧会提示「非我方决策」。
- 这一局是**旧版本流水线**生成的（`status.json` 里 `pipeline_version` 落后）。跑一次 `一键重建解读.bat` 就会补上。
- 这一手你**和 Mortal 一致**（不算恶手），不生成解读条目，权重表也就没有内容。

## 9. 解读里「有效牌」为什么把 19 种全画出来

因为省略会误导：写「+11」时读者没法知道具体是哪 11 种。现在把全部有效牌画出来（按万→筒→索→字排序，
每张下面标剩余枚数），右侧写明「几种 / 几枚」。正文里提牌名的地方也换成了牌图，
所以你看到的是牌，不是「2万」两个字。

**「完整对照图」不再出现**：牌效页已经有 13 张手牌 + 全部有效牌 + 改良牌，比那张 600×334 的
PNG 更细；PNG 仍然生成，只在 `library/img_layout/` 里归档备查。

## 9.1 打点（宝牌 / 役种 / 番数）会解释吗

会，分四层：

| 判据 | 例子 |
|---|---|
| 宝牌 | 「打 X 后留 2 枚宝牌，打 Y 只剩 1 枚」 |
| 断幺 | 「打 X 后全 2~8，断幺成立，白捡一番」 |
| 役牌 | 「打 X 保住役牌 白；已成刻子就是 1 番，只有对子时需要碰或再摸一张成刻」 |
| 通用番数 | 「打 X 是「混一色」3 番 3900 点，打 Y 只剩「断幺九」1 番」 |

番数由 `yakucalc.outline()` 对两种切法各算一次，可复算；覆盖混一色、清一色、七对子、
对对和、平和、一气通贯、三色同顺、一杯口。番数相同时也会写「这一手的差别不在打点」。

## 9.2 哪些手算恶手？门槛和颜色怎么调

两道关，都能在设置里改：

**① 门槛（权重差）** —— 低于门槛的手不进库，页面上也翻不到。默认 **10%**：

| 门槛 | 效果 |
|---|---|
| 10%（默认） | 「Mortal 有六成把握而你选了别人」以上全部收进来 |
| 30% 以上 | 只留明显不同选，库会瘦很多，小分歧不再出现在面板里 |
| 5% 以下 | 会把「和 Mortal 几乎一致」的手也收进来，恶手数虚高，不建议 |

**② 门槛之上只分两档，都算恶手**：

| 档 | 默认阈值（权重差） | 表现 |
|---|---|---|
| 严重 | ≥ 50% | 巡目染红 |
| 中等 | 门槛 ~ 50% | 巡目染橙 |

两档**都出解读、都计入「· 恶手 N 处」、都能被「上一 / 下一恶手」跳到**，
区别只在颜色——红的是「和 Mortal 差得很远」，橙的是「差得不多但确实不一样」。

**③ 右上角徽章的「损失」** 是另一套刻度，只看期望损失 Q（默认 ≥0.70 严重 / ≥0.30 中等 / 其余轻微），
和巡目颜色无关。看到「权重差 100pt · 损失 轻微」不用奇怪：Mortal 很确定你打错了，
但两张牌其实差不多，这种手不亏。

**改门槛后要重跑**：门槛在**提取**那一步生效，已有牌谱不会自己变。
保存设置后跑一次「一键重建解读.bat」（只补缺；脚本会比对状态里记录的门槛，不一致就重提）
或 `rebuild.bat`（全量重算）。

## 9.3 「三分钟上手」每次都弹？

旧版本确实每次都弹：pywebview 默认 `private_mode=True`，每次启动换一个临时用户目录，
`localStorage` 全部清空，等于「永远第一次」。现在改成持久化目录，且状态写进配置文件：

- 弹窗底部勾着 **不再自动提示**（默认勾选）→ 关掉后不再弹；
- 取消勾选再关 → 下次启动还会提醒一次；
- 想重看：设置 →「使用说明 / 常见问题」；
- 状态在 `mortal-coach.json` 的 `ui.welcome_done`，换机器 / 清缓存都不丢。

## 10. 换机器 / 搬到另一台电脑

1. 拷整个程序目录（或解压发行包）。
2. 把 `library` 放在你能读写的任意位置，在设置里指过去（默认是程序目录下的 `library`）。
3. **不要**拷 `chrome-profile`：旧机器的 cookie 解不开，新版会自动作废重建；手动拷过去反而多一次人工验证。
4. 新机器第一次分析可能要求点一次「确认您是真人」，之后就好了。
5. 实例目录下的 `chrome-profile.old` 是自动备份的旧 profile，确认新 profile 正常后可以删。

## 11. 双击没反应 / 杀软报毒

- onefile 打包的 exe 首次启动会解压到临时目录，慢几秒是正常的；Windows Defender 也可能扫一会儿。
- **先核实再处理**，顺序是：① 确认是从官方 Release 下载的，版本号与页面一致；
  ② 用 `SHA256SUMS.txt` 校验压缩包（`certutil -hashfile <zip> SHA256`）；
  ③ 看告警的具体名称与路径，是「未识别程序」的通用启发式，还是指认了具体行为。
- 只有确认来源与校验和对得上时，才谈「把程序目录加入白名单」——这一步不是通用解法，
  来路不明的文件不该放行。程序本身不装服务、不常驻后台。
- 想看详细诊断：`mortal-coach.exe --selftest`（机器可读的环境自检，缺项时退出码非 0）；
  `--shot` 会开 CDP 调试端口 9333。

## 12. 概念类误解

**「Mortal 的结论和网页版不一样」**
模型不同（4.1a / 4.1b / 4.1c / 4.0 / 3.0）结论就不同，rating 与 Q 值**不能跨模型比较**。要复现别人的结论，先对齐模型。

**「Mortal 选的不就是全局最优吗」**
不是。它算的是**这一巡**的最优，不是整局最优；而且它不知道你之后会怎么打。所以解读里所有「原理」都是
「在当前牌型与场况下为什么这样更优」，不是「照做必胜」。

**「恶手是怎么定的」**
**门槛**看权重差（默认 ≥10pt 才入库，可在设置里改；P = softmax(Q/0.1)，τ=0.1 使分布很尖）。
门槛之上的手**全部算恶手、全部出解读**，只按权重差分两种颜色（≥50% 红、其余橙）。
另外右上角徽章的「损失」是另一套刻度，按期望损失 Q 算（默认 ≥0.70 严重 / ≥0.30 中等），
和巡目颜色互不影响。

**「为什么有的好牌没被标成恶手」**
阈值是固定的；另外只解读**你**的决策点，别家的选择不评价。

## 13. 数据与隐私

- 只有牌谱会发到 `mjai.ekyu.moe`，和用网页版提交是同一件事。
- 解读、权重、对照图全部本地计算，不调任何大模型 API。
- 想彻底清空：删掉 `library` 目录（或在设置里换一个空目录）。
- 只删 `img_layout/` 不影响解读文字；`report/` 是最有价值的部分，留着就不用重新提交 Mortal。
