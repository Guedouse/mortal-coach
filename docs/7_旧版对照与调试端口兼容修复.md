# 旧版对照与调试端口兼容修复（提交协议 build 6）

## 已确认的实现与差异

用户提供的旧版仍使用系统 Chrome／Edge、独立应用资料目录和 Chrome DevTools Protocol（CDP）。提交脚本填表、等待真人验证、调用表单提交，再监测最终报告地址，自动下载报告并生成中文解读。它没有使用另一个免验证接口。

浏览器启动方式存在一个关键变化：旧版使用明确的非零调试端口，新版改为将 `--remote-debugging-port=0` 直接传给浏览器。受测试环境中，两种启动模式对验证流程的结果不同。

隔离对照结果：

| 对照条件 | 结果 |
|---|---|
| 新版代码、Chrome、端口参数为 0 | 复盘控件失败，错误码 600010 |
| 旧版脚本和旧版启动参数、旧应用资料的测试副本 | 取得验证响应；旧脚本未区分两个表单，不能单凭此结果证明复盘成功 |
| 同一新版代码和测试资料，只将启动参数改成明确的非零空闲端口 | 取得 reviewForm 复盘控件的验证响应 |
| 新版代码、明确的非零空闲端口、完全空白的新资料目录 | 同样取得 reviewForm 验证响应 |

因此，本次修复不依赖从旧版本迁移 Cookie，也不依赖用户日常浏览器资料。Cloudflare 的内部判定不公开；以上证明本机环境存在可复现的启动兼容回归，不代表网站永久免验证。

## 实施方式

保留原来的全自动流程，不安装扩展，不要求复制最终报告地址。仍使用应用独立资料目录，需要人工确认时显示浏览器。

由操作系统分配空闲端口，再把明确的非零端口传给 Chrome／Edge。没有回退到全局固定 9222，也不复用别人已经开启的调试端口。程序从本次子进程标准错误流读取其 Browser WebSocket 端点，并核对 `/json/version` 返回相同端点后才连接。端口在释放后被其他进程抢占时，端点不符则拒绝连接。复用和关闭时也核对端点。

不会覆盖或修改浏览器检测属性，不自动点击验证码，不复制日常浏览器 Cookie。保留已有的失败提示、主动重载、普通浏览器手动导入备用入口。

## 打包要求

- lite 和 full 均不附提交用 Chromium；没有系统 Chrome／Edge 时提示用户自行安装。
- full 仅额外附 WebView2 界面运行时。它用于显示应用，不用于向 Mortal 提交牌谱。
- 发行包由白名单重新构建，空库、空路径配置，无个人浏览器资料和历史牌谱。
- 旧版压缩包含浏览器资料和个人牌谱，不能直接作为新的公开发行资产。

## 复核

检查设置中的提交脚本版本应为 build 6。粘贴新牌谱后，应自动启动系统浏览器、提交、进入评分、取得最终报告并生成中文解读；必要时只需在弹出的窗口完成真人验证。

本次还对用户最近失败的牌谱，在独立测试库运行真实端到端分析。具体测试结果与安装校验保存在本次工作记录中；原始牌谱链接、日志和浏览器资料不进入发行包。
