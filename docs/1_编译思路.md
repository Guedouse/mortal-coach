# 编译思路 · mortal-coach（桌面版）

这份文档说明**这个 App 是怎么拼起来的**：为什么选这个形态、每一层做什么、怎么打包、踩过哪些坑。
照着做可以在任何一台 Windows 机器上从源码重建出 `mortal-coach.exe`。

---

## 一、为什么是「pywebview + 内嵌 HTTP 服务」

需求是：双击图标 → 一个窗口 → 左边牌桌、右边解读，能输入牌谱链接，离线可用。

三条路都试过或评估过：

| 方案 | 结果 |
|---|---|
| **直接用浏览器**（`serve_kd.py` + Chrome） | 能用，但要自己开终端、记端口；链接分析还必须守着一个 Chrome 窗口等 Turnstile |
| **Electron / Tauri** | 功能齐全，但要拉 Node 运行时或 Rust 工具链，包体 100 MB+，为了一个只读页面不值 |
| **pywebview（选中）** | Python 一行 `create_window` 就是一个原生窗口，内核是系统自带的 **WebView2**（Win10/11 预装），exe 只有 16 MB |

关键点：这个页面本来就是纯前端（`assets/kd` 是自写的回放器，86 KB 的 `index.js`），
不需要 Node，也不需要打包器。用 pywebview 相当于**给它套一个原生窗口 + 一个本地静态服务**。

## 二、三层结构

```
┌──────────────────────────────────────────────┐
│  pywebview 窗口（WebView2 内核）              │
│   加载 http://127.0.0.1:8777/kd/?data=...     │
└───────────────┬──────────────────────────────┘
                │ 同源 HTTP（静态文件）
┌───────────────▼──────────────────────────────┐
│  ThreadingHTTPServer（Python 标准库）         │
│   根目录 = <ROOT>/assets   ← 注意不是 assets/kd│
│   /kd/…  → 页面     /img_layout/… → 牌型对照图 │
└───────────────┬──────────────────────────────┘
                │ js_api（window.pywebview.api）
┌───────────────▼──────────────────────────────┐
│  Api 类：submit_link(url)                     │
│   起 Chrome(9222) → tools/submit_auto.mjs     │
│   → 下载 report.json → pipeline_one.py        │
└──────────────────────────────────────────────┘
```

### 1. 服务根为什么是 `assets/` 而不是 `assets/kd/`

页面里的牌型对照图是用 **绝对路径** 引用的：`/img_layout/261118B_0012.png`。
图片实际在 `library/img_layout/`，所以服务根必须抬到 `assets/`，页面路径才是 `/kd/index.html`。
`mk_coach.py` 的 `web_img()` 也是按「父目录名/文件名」生成 URL 的，两边必须对齐。

### 2. 端口

按 `8777 → 8778 → 8779 → 8780` 顺序取第一个空闲端口（`port_open()` 探测）。
所以同时开两个实例不会打架，后开的落到 8778。

### 3. js_api 桥

`webview.create_window(..., js_api=api)` 会把 `Api` 的公开方法挂到 `window.pywebview.api`。
页面里只用到两个：

- `submit_link(url, fmt, model, seat)` —— 粘贴牌谱后的整条链路（见下）；三个参数来自侧栏下拉
- `open_game(tag)` —— 仅回执，切局其实是前端改 `?data=` 完成的（不刷新窗口更快）。

`js_api` 的返回值必须是可 JSON 序列化的 dict，前端才能 `await` 到。
参数个数可以随前端 `window.pywebview.api.submit_link(a, b, c, d)` 一一对应，不必包成对象。

### 4. ROOT 定位（exe 放哪都能跑）

```python
def find_root():
    cands = []
    if getattr(sys, "frozen", False):
        cands.append(Path(sys.executable).resolve().parent)   # exe 所在目录
    cands += [Path(__file__).resolve().parent.parent, Path.cwd()]
    for c in cands:
        if (c / "assets" / "kd" / "index.html").exists():
            return c
```

判定条件不是「exe 在哪」，而是「哪个目录下有 `assets/kd/index.html`」。
好处：exe 和源码共用一套逻辑；把整个文件夹拷到别处、换台机器也照样能跑。
（早期这里还写死过一个绝对路径，已删除 —— 那属于「和别的目录联动」，不该有。）

> 约束：`mortal-coach.exe` 必须和 `assets/`、`scripts/`、`tools/`、`runtime/` 同级。
> 可以放桌面快捷方式，但不要把 exe 单独拷走。

### 5. 独立运行：`runtime/` 里自带解释器与 Node

冻结之后 `sys.executable` 是 `mortal-coach.exe`，**不是** Python 解释器；
把 `scripts/pipeline_one.py` 交给它就等于又开一个 App。所以发布包自带运行时：

```
mortal-coach.exe
assets/  scripts/  tools/  library/
runtime/python/python.exe     ← Python 3.13 + Pillow（制图用），53 MB
runtime/node/node.exe         ← Node 22，提交 Mortal 用，84 MB
library/                      ← 牌谱库：report/ coach/ img_layout/ logs/ work/
```

```python
def find_py():
    cands = [_exe("python", "python.exe"),            # 包内优先
             CONFIG.get("python") or "",              # 其次设置里指定的
             os.environ.get("MORTAL_COACH_PY") or "", # 再次环境变量
             "python",                                # 最后 PATH
             ]
    if not getattr(sys, "frozen", False):
        cands.append(sys.executable)
    …
```

`find_node()` 同理；`find_chrome()` 依次看设置 → `MORTAL_COACH_CHROME` → 常见安装位置
→ 注册表 `App Paths\chrome.exe / msedge.exe`。**没有任何写死的开发机路径。**

`--selftest` 用一个 JSON 报出实际用的解释器与缺什么：

```bat
mortal-coach.exe --selftest
{"app": "<安装目录>", "library": "<安装目录>/library",
 "config": "…\\mortal-coach.json", "python": "…\\runtime\\python\\python.exe",
 "node": "…\\runtime\\node\\node.exe", "chrome": "…\\chrome.exe", "problems": []}
```

界面启动时也会调 `env_report()`，缺依赖直接把原因写在侧栏状态条里，
不会等你点了「分析」才莫名其妙失败。

Pillow 是给 `mk_layout` 画 600×334 对照图用的；没有它流水线只跳过制图，
解读、坐标、页面内手牌图都不受影响（状态文件会记一条 warning）。

## 三、链接分析的链路（唯一需要联网的一步）

```
粘贴链接 / 对局 ID（主页左卡片先选：格式 / Mortal 模型 / 座次）
  └─ normalize_pasted_input() 取第一个 http 地址、去尾部标点；
                          没有协议头的「域名/路径」补 https://（game.maj-soul.com/1/?paipu=…）
  └─ guess_format()       自动识别：http → 链接；数字_24hex → 姬麻将；
                          { 开头 → 天凤6；字母数字串 → 一番街(Riichi City)对局 ID
  └─ seat_from_log_id()   一番街 / 姬麻将 ID 末尾 @N 即座位
  └─ 【新】雀魂链接里没有玩家 ID 时（形如 ?paipu=261117-xxxx，没有 _a123456789）
        Mortal 只会回一行纯文本错误 → 先在本地拦下，提示「请选座次」，不浪费一次提交
  └─ ensure_chrome()      没开就起 Chrome: --remote-debugging-port=9222
                          --user-data-dir=… --window-position=-2400,0（挪到屏幕外）
  └─ tools/submit_auto.mjs '{"url":…,"format":…,"model":…,"seat":…}'
        CDP 连上 9222 → 设 input-method radio（并调页面 changeInputMethod 展开输入框）
        → 原生 setter 写字段 + 派发 input/change（让页面 changeURL 也跑一遍）
        → 回读字段值，和要提交的字符串不一致就打 WARN_VALUE_MISMATCH
        → 等 Turnstile token（首次可能要 40~60 秒）→ requestSubmit()
        → 轮询 URL：只有 /report 或「带 data 的 killerducky 页」才算报告页
  └─ 从 URL 里取 ?data=…，urljoin 成绝对地址并校验主机
  └─ 下载 → 校验 HTTP/Content-Type/JSON 结构（mjai_log + review.kyokus + player_id）
  └─ 原子写入 library/report/<标签>.json
  └─ scripts/pipeline_one.py <report> <标签>    ← 16~33 秒，出解读 + 图 + 状态文件
     （恶手门槛来自 scripts/badcfg.py：MC_BAD_THRESH → mortal-coach.json 的 bad.thresh → 0.10；
       状态里记 bad_thresh，改门槛后 rebuild_all 会自动重提那一局）
     （只改了文案 / 判据、恶手集合没变时，用 scripts/refresh_text.py 重算文字即可，
       它复用 bad_moves.json，不动坐标与 PNG；几百手约 8 分钟，可只传标签重算单局）
  └─ 前端轮询 coach/<标签>.json → 跳到第一处恶手
```

> 重建脚本走 `scripts/paths.py` 解析牌谱库（`--library` → 配置文件 → `MC_LIB` → 默认），
> 界面里改过库之后，两个 BAT 写的就是同一个库，并在第一行打印实际路径与来源。

**报告页判定必须是 URL 规则，不能是「不是首页、不是排队页」**：
早期写法 `!/progress && !/zh-cn.html` 会把**停在首页**（提交没成功）也当成报告页，
于是 Python 拿不到 `data` 参数，用户只看到「报告地址里没有数据参数」，看不出失败在哪一步。
现在规则在 `tools/url_rules.mjs`，只认两种：

| 认 | 不认 |
|---|---|
| pathname 是 `/report` 或 `/report/…` | 首页 `/`、`/index.html` |
| pathname 含 `killerducky` **且 data 非空** | `/progress`、`/review` 的错误文本页 |
| | 任何非 `mjai.ekyu.moe` 的主机 |

规则有单测：`node tools/test_rules.mjs`（19 条，覆盖首页、排队页、相对 data、伪造子域）。

**错误标记**（Python 靠这些行判断失败原因，不靠猜）：

| 标记 | 含义 | 界面提示 |
|---|---|---|
| `NO_PAGE` | 没有 mjai 页面 | 浏览器没打开官网 |
| `NO_TOKEN` | 人机验证没出 token | 再点一次，可先关掉屏幕外的 Chrome |
| `NO_FORM` | 首页表单找不到 | 官网可能改版 |
| `PAGE_ERROR <文本>` | 官网把错误渲染成纯文本页 | 原样转成中文提示（如缺座位） |
| `NO_REPORT_URL` | 提交了但没进报告页 | 链接失效 / 排队超时 |
| `REPORT_TIMEOUT` | 报告页 URL 对但牌桌没渲染 | 稍等重试 |

**为什么必须带界面的 Chrome**：Cloudflare Turnstile 只在真实渲染的窗口里发 token。
`--headless=new`、改 UA、CFT 131 全部试过，90 秒仍是 0 字符；带界面 + 窗口移出屏幕才拿得到。
注意 cloudflare 有时要 **40~60 秒**才把 widget 渲染出来，所以等待策略是「先耐心等 100 秒」，
一上来就刷新页面会把已经等到的进度丢掉。

**为什么还要看 DOM**：光有报告页 URL 不够，牌桌没渲染完就读不到局数、牌河。
所以判定是「URL 命中规则 **且** `.info-round` / `.grid-main` 出现」。

**干跑自检**（不消耗 Mortal 配额、不踩 Turnstile）：

```bat
set MC_DRY=1
node tools\submit_auto.mjs "{\"url\":\"ch35u1e9nc70954ah9n0@3\",\"format\":\"riichi-city-log-id\",\"model\":\"4.0\",\"seat\":\"3\"}"
:: 打印 SET、SNAP 后退出，SNAP 就是实际会提交的表单值
```

**标签规则**：`261118`（从链接里的 6 位日期取），同日第 2 局自动 `261118B`。
`next_tag()` 会同时检查 `report/` 与 `coach/` 是否已存在同名文件。

**日志与状态**：每次提交写 `library/logs/<标签>.log`（含 submit_auto 全部输出、报告校验结果、
pipeline 输出）；每次流水线写 `library/coach/<标签>.status.json`。
出问题先看这两个文件，不要靠猜。

## 四、打包（实测可用）

```bat
cd app
pyinstaller mortal-coach.spec --distpath .. --workpath ..\build --clean --noconfirm
```

`app/mortal-coach.spec` 等价于下面这条命令（`--collect-all webview` 不能少）：

```bat
pyinstaller --noconfirm --onefile --windowed ^
    --icon icon.ico --name "mortal-coach" ^
    --distpath .. --workpath ..\build ^
    --collect-all webview main.py
```

要点：

| 参数 | 为什么 |
|---|---|
| `--onefile` | 单文件 16 MB，拷贝方便（解压到 `%TEMP%` 再跑，首次启动 8~13 秒属正常） |
| `--windowed` | 不要黑框控制台 |
| `--collect-all webview` | pywebview 的动态库、`webview/lib` 下的 DLL、`pythonnet` 的 clr 都要收进去，不加这个启动即报 `Python.Runtime` 找不到 |
| `--icon` 用**绝对路径** | 用相对路径时 PyInstaller 把工作目录当成 `app/`，找不到 `app/icon.ico`（踩过） |
| `--distpath .` | 让 exe 直接落在项目根，和 `assets/` 同级 |

**前置依赖**（`envs/default` 里已装）：

```
pywebview 6.2.1   pythonnet（WebView2 后端必需）   PyInstaller   Pillow   pylnk3
```

WebView2 运行时是 Win10/11 自带的；确实没有的话装一次 [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) 即可。

### 图标

`app/make_icon.py` 用 PIL **画**出来，不依赖外部素材：象牙底渐变 + 绿色「發」+ 四角绿点，
导出 16/32/48/64/128/256 六个尺寸打进 `icon.ico`。改配色改几个常量重跑即可。

### 桌面快捷方式

**不能用 PowerShell 的 `New-Object -ComObject WScript.Shell`** —— 本机安全策略会拦。
改用纯 Python 的 `pylnk3`：

```python
pylnk3.for_file(str(EXE), lnk_name=str(lnk), description="mortal-coach · 日麻对局复盘",
                icon_file=str(EXE), icon_index=0, work_dir=str(EXE.parent))
```

跑 `python app/make_shortcut.py` 即在桌面生成 `mortal-coach.lnk`。

## 五、调试手段（改前端时很有用）

exe 是 `--windowed`，看不到控制台，所以留了一个开关：

```bat
mortal-coach.exe --shot        :: 或 --devtools
```

它做两件事：给 WebView2 加 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9333`，
并 `webview.start(debug=True)`。之后就能像调试网页一样连上去：

```bat
set CDP_PORT=9333
node tools\cdp.js eval "JSON.stringify({ply: MM.GS.ply_counter, sev: document.getElementById('cp-sev').textContent})"
node tools\cdp.js shot D:\tmp\a.png
node tools\cdp.js nav "http://127.0.0.1:8777/kd/?data=report/261118.json&hand=0&ply=18" 2500
```

`MM` 是 `index.js` 主动暴露的调试入口（`export default { main, GS, debugState }`），
`MM.GS.ply_counter` / `MM.GS.hand_counter` 就是当前停留的坐标，跟 `bad_moves.json` 的 `kd_hand/kd_ply` 同源。

## 六、踩过的坑（按疼痛程度排序）

1. **`body { max-width: 1100px }`** —— 回放器原本是单栏，加了解读面板后被挤出屏幕，看起来像「面板没渲染」。
   改成 `1680px` 并给 `.outer` 加 `align-items: flex-start` 才对齐。窗口宽 1650 是配合这个值定的。
2. **`run_review.sh` 把首页误判成报告页** —— 它的判据是「页面 HTML 长度 > 5000」，首页也满足。
   换成 `submit_auto.mjs`（等 URL 变成 `/report`，且排除 `/progress` 中间页）。
3. **下载报告 403** —— `urllib` 默认 UA 被 Cloudflare 挡，必须 `headers={"User-Agent": "Mozilla/5.0"}`。
4. **exe 里 `__file__` 不是源码路径** —— 冻结后要用 `sys.executable`；pywebview 的 `webview.start()`
   必须在主线程调用，HTTP 服务放 daemon 线程。
5. **`Path("")` 退化成当前目录** —— 判断图片是否存在前必须先判空串，否则 `web_img("")` 会返回一个莫名其妙的路径。
