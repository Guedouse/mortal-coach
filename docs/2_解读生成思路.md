# 牌局解读生成思路

这份文档说明：**一份 Mortal 报告，怎么变成右侧面板里那段中文解读 + 那张对照图**。
全流程本机计算，不联网、不调用任何大模型、不消耗任何 token；一局约 **33 秒**。

```
report.json
   │
   ├─① 恶手筛选        extract_core.extract()      P(我方) 比 P(最优) 低 ≥10pt
   ├─② 牌理核算        mjcalc / mjeval             向听 · 进张 · 好形率 · 各家安全度
   ├─③ 中文成文        explain.gen()               14 类模板 + 两类语气
   ├─④ 坐标映射        extract_core.build_positions()  全局事件号 → (hand, ply)
   └─⑤ 配图与查表      mk_layout / mk_coach         600×334 对照图 + coach/*.json
```

---

## 一、输入：只需要一份报告

以前的做法要三样东西（Akagi 的 `mjai.jsonl`、手写的座位、另存一份 report），
现在只读 **`library/report/<标签>.json`** —— 也就是 `mjai.ekyu.moe/report/xxxx.json` 原文件。
它自带全部所需信息：

| 字段 | 用途 |
|---|---|
| `player_id` | 座位号（0东 1南 2西 3北），不用再手填 |
| `mjai_log` | 完整事件流（约 800~1000 条），用来重建牌河、副露、立直、宝牌 |
| `review.kyokus[*].entries[]` | 每一次决策的 `state.tehai`（手牌）、`tile`（摸到/被切的牌）、`expected`、`actual`、`details[].q_value` |
| `review.rating` / `total_reviewed` / `total_matches` | 顶部评分卡 |

**关键**：报告里**没有事件下标**，而 `bad_moves` 需要靠事件下标回查牌河。
所以有一个「指纹对齐」步骤（见第三节），这是整条链路唯一的非平凡环节。

## 二、① 恶手筛选：权重差

Mortal 对每个候选动作给一个 `q_value`。先用温度 `T=0.1` 做 softmax 得到概率：

```
P(a) = exp(q(a)/T) / Σ exp(q(b)/T)
```

`T=0.1` 让分布极尖锐（几乎只有一个动作有概率），所以判据是：

> **P(实际动作) 比 P(最优动作) 低 ≥ `thresh`** → 记为恶手（入库门槛，默认 0.10）。

门槛是配置项（`mortal-coach.json` 的 `bad.thresh`，设置面板里也能改），
`scripts/badcfg.py` 是流水线侧的读数入口：环境变量 `MC_BAD_THRESH` → 配置文件 → 默认 0.10。
门槛之上**全部解析**：都出解读、都标记、都计入「恶手 N 处」，没有「入库了但不算」的中间态。
（旧版本门槛固定 0.30，后来固定 0.10，现在交给用户定。）
同一手会被报告记两条（立直回合），用 `(事件下标, expected 动作)` 去重。

**为什么门槛之上还要分颜色**：`T=0.1` 下这个概率差会饱和——P 差 90pt 与 99pt 都可能只差 0.05 的 Q；
反过来 P 差 15pt 也可能亏掉半手牌。所以每条记录额外算两个量：

- `gap = P(最优) − P(实际)`：**权重差**，就是页面上那张权重表里的差；
- `Q损 = Q(实际) − Q(最优)`：**期望损失**，这一手真正亏掉多少。

早期按 Q 损固定切五档（可忽略 <0.10 / 轻微 <0.30 / 中等 <0.70 / 明显 <1.50 / 重大 ≥1.50），
问题有三：入口是按权重差切的、分档却按 Q 损，两个量纲；「可忽略」仍被入口收进来，
标签自相矛盾；五档之间没有对应的行动差别——用户只关心「这一手要不要复盘」。

现在只保留**两种颜色 + 一个徽章**（设置面板里就是这几项）：

| 用在哪 | 判据 | 严重 | 中等 | 轻微 |
|---|---|---|---|---|
| **巡目下拉的颜色**（门槛之上全部算恶手） | 权重差 | ≥ 50% | 门槛 ~ 50% | 不设这一档 |
| **解读面板右上角的「损失」** | 期望损失 Q | ≥ 0.70 | 0.30 ~ 0.70 | < 0.30 |

**为什么不合成一个判据**：权重差混着「Mortal 有多确信」，Q 差只看代价，两轴 Spearman 0.80
但盲区方向不同。合成一个就得仲裁，用户还得理解「严重但损失轻微」到底算哪档；
分开反而一句话能讲清——**颜色回答「差得多不多」，徽章回答「这手值不值得心疼」**。

**为什么不再要第三档**：门槛本来就是「值不值得看一眼」的界线，界线之上再划一个
「其实可以不看」的档，等于把刚划的线抹掉。要么不收，要么就是恶手——分颜色足够表达轻重。
门槛之上的手按权重差自然分成两堆：超过严重线的染红，中间段染橙，红的大约占七成左右
（具体比例因人而异，不用当成基准）。

**为什么默认门槛是 10pt 而不是更低**：绝大多数决策点的权重差都不到 5pt，
那些基本是「和 Mortal 完全一致」，收进来只会让「恶手 N 处」失真；
10pt 相当于「Mortal 有六成把握而你选了别人」，往下就进入噪声区了。

徽章和颜色无关：同一手完全可能是「权重差 100pt · 损失 轻微」
——Mortal 极度确信该打这张，但两张牌其实差不多。这种手不少，属于正常现象。
局数下拉不做染色（一局里多数巡都可能是恶手，整局上色等于没有信息量），只写「· 恶手 N 处」。

三项阈值都存在 `mortal-coach.json` 的 `bad`（`thresh` / `gap` / `loss`），
由 `assets/kd/badlevel.js` 统一算档（页面与 `tools/test_badlevel.mjs` 共用同一份实现，
避免两处漂移）。旧配置里的 `metric/severe/medium`、上一版三档写法都会自动迁移。
改 `thresh` 只影响以后重跑的提取；`scripts/rebuild_all.py` 会比对状态里记录的
`bad_thresh`，不一致就重提那一局。

> 权重的缺点是在 90% 以上会饱和——Q 差 0.3 与 0.9 都可能是 99 对 1。
> 所以「谁更贵」这件事交给徽章的 Q 档，权重差只负责「值不值得点开看」。

## 三、指纹对齐：报告条目 → 事件下标

报告的 `entries` 是按局组织的，`mjai_log` 是一条时间线。要把两边接上：

1. **在事件流里记录候选点**：我方摸牌（`tsumo`）后记 `(下标, 手牌多重集, 摸到的牌)`；
   别家打牌（`dahai`）时记 `(下标, 我手牌, 打出的牌)`（供鸣牌窗口用）。
2. **key = `(排序后的手牌元组, 牌)`**，做成 `dict[key] → [下标...]`。
3. 遍历报告条目，用 `Counter(state.tehai)` + `tile` 组同样的 key 去查；
   同 key 多次出现按顺序 `pop(0)`（同一手牌摸到同一张牌两次的情形极少，但存在）。
4. 查不到就退化成「上一次同 key 的下标」（立直后被记两条时会走到这条分支）。

对齐率是健康指标：**12 局全部 100% 命中**（281/281）。
新局如果出现大量未对齐，通常意味着报告版本变了或事件类型有新成员。

## 四、② 牌理核算：数字从哪来

| 指标 | 实现 | 说明 |
|---|---|---|
| 向听数 | `mjcalc.shanten()` | 位运算，单次 ≈0.46 ms |
| 进张（种/枚） | `mjcalc.ukeire(hand, calls, visible)` | ≈15.7 ms；`visible` = 四家牌河 + 副露 + 宝牌指示 − 我的手牌 |
| 好形率 | `mjeval` | 两面/嵌张/边张加权 |
| 改良牌 | `explain.improve_info()` | **候选筛选 + 精确验证**：只对浮牌邻张、嵌张升级位、役牌本身做全量验证，不做 34×14 全枚举（否则 20 分钟一局） |
| 安全度 | `mjeval.safety_grade()` | 查表，见下 |
| 役牌/宝牌/断幺 | `explain` 内的 `_yakuhai_kind` / `discard_value` | 自风 = `ESWN[(seat − dealer) % 4]`，**必须含自风与场风**，漏了会把「留自风」误判成牌效问题 |

### 安全度分级（score 越高越安全）

```
现物 100 ＞ 绝张字牌 98 ＞ 现二/一字牌 96/86 ＞ 两筋456·筋19 86
       ＞ 生牌字牌·筋28 65·筋37 62 ＞ 456筋牌 55
       ＞ 无筋幺九 44 ＞ 无筋2/8 40 ＞ 无筋3/7 37 ＞ 无筋中张 9
```

三条硬规则：

1. **筋只看「该家自己」的牌河**，别家打的不算；
2. 另计**双筋**与**壁**（该牌 ±3 已见 4 张 → 挡掉一组两面）；
3. 面对多家攻击时，**取所有攻击者里的最坏档**，不是只看最显眼的那一家。

## 五、③ 中文成文：14 类模板、两种语气

`explain.gen(rec)` 返回 `(标签, 严重度, 正文)`。正文按行分块，行首决定颜色
（`【】`黄标题、`场况`灰、`①②`蓝、`原理`灰、`结论`绿、`Mortal 评分`金、`—— 参考`暗灰），
Excel 富文本和网页面板共用这套规则。

### 先分三类：攻、守、以及「攻守同向」

`attack_defense()` 先算三个量 —— **对手威胁 / 自己本钱 / 自己退路** —— 再据 Mortal 的选择定语气。
这三样是「为什么要攻 / 为什么要守」的全部依据，每一句都落在具体数字上，不写套话：

| 量 | 怎么算（`explain.py`） | 输出例 |
|---|---|---|
| 威胁 | `threat_lines()`：亲家立直 3 级、子家立直 2 级；1 副露 1 级、2 副露以上 2 级；两家立直直接 3 级 | 上家已碰8万（共 1 副露），其中 3 张是宝牌；下家已立直、牌河 5 张 |
| 本钱 | `own_lines()`：打完后的向听 + 进张枚数（≤ 一向听才折算每巡摸到率）+ `yakucalc.outline()` 的主线役与成型点数 | 1 向听、进张 6 枚（残 47 张，每巡约 13% 摸到）；打点走「断幺九」，成型约 1 番 1000 点 |
| 退路 | `_escape_line()`：对**最危险的一家**，手里还剩几张 ≥86 分的强安牌（现物 / 筋19 / 两筋456 / 现字牌） | 1 张强安牌（7筒）—— 够再挡一手，之后就要开始拆搭子了 |

**攻的三种情形，说法不一样**（这是「为什么敢攻」的关键）：

- **攻守同向** —— Mortal 这张牌比实战那张**又快又明显更安全**（安全度差 ≥ 12 分且向听不差）：
  首行写「不用取舍」，直接点明这一手没有「该攻还是该守」的纠结，别再讲一通牌效；
- **继续做牌** —— 自己还在 2 向听以外：承认这不是「押胜负」，是继续补牌型；
  同时如实写出 Mortal 的局限（它只看这一巡最优、不提前储备安牌，所以没听牌前一律按牌效走）；
- **继续进攻 / 谨慎** —— 自己已听牌或一向听：才谈「押得起」，并按手里强安牌张数
  （≥2 张 = 有退路 / 1 张 = 退路很窄 / 0 张 = 守也守不住）给出**为什么不去弃和**。

**守的分档**：Mortal 打出的牌 ≥86 分 → 「该守」（首行直接点名它是现物还是筋）；
<86 分且威胁 ≥2 级 → 「该守」（承认手里没有现物，只能退到次优档）；
威胁只有 1 级 → 「偏守」（承认对手威胁不大，是自己这手牌没快到值得为它冒险）。
「为什么不攻」按自己的向听分三种：还在 2 向听以外（追不上）、打进攻牌能保向听（用一手换一次铳）、
两边向听一样（只差几枚进张，铳率却差两档）。

**A. 防守类（标签 `安全优先`）**
触发条件：场上有攻击者（立直 / 任意副露），且 Mortal 选的牌安全度明显更高（差 ≥ 12 分 ≈ 铳率 1.7pp）。
这类**只讲防守逻辑**，一个字都不写进张/向听/搭子形状：

```
【为什么打 X】
场况：<巡目、场上威胁>
点数：我方 25300（2位） · 下家 21900（3位） · …
顺位：距 1 位（上家）7200 点，二位，4 番可反超一位。
手牌：听牌 · 面子 3 · 搭子 1 · 浮牌 1 · 门前
做牌：走「断幺九 + 平和」这条线，基本成形（成型后 2 番，约 2000 点）。切掉 9筒 即可。
攻守：这一手该守 —— 4筒 是「现物(绝对安全)」，可以先把这一手安全地过掉。
   威胁：…／本钱：…／为什么不攻：…／退路：…
① 安全（决定性）：逐个对手核对，取最坏的一家 ——
原理：<铳率表排序，只做比较不说绝对值>
结论：…
```

**B. 进攻·牌效类（其余全部）**
必须写出**两种切法各自的进张**（种数 + 枚数）和「丢 X 赚 Y」的账。
牌子本身不进文字：两手 13 张与**全部有效牌**由前端 `handBlock()` 画成牌图（每张下标剩余枚数），
文字只写判据、原理与结论，避免同一份信息既画一遍又列一遍。

```
【为什么打 X】
场况：…
点数：…
顺位：…
手牌：…
做牌：…
攻守：继续进攻 —— 对手在攻，但这一手押得起：本钱够，退路也在。
   威胁：…／本钱：…／为什么不弃和：…／退路：…
① 牌效（决定性）：牌效上与另一手打平（同为 3 向听、进张 67 枚），于是比「哪张留着最没用」。
   南：孤张字牌，切牌价值 8；靠张重复度 0/0；场上已见 0 张、剩 4 枚
   → 南 是孤张字牌，切掉它对现有牌型毫无损失。
原理：…
结论：南 是当前最该先切的一张。
```

### 打点判据（2026-11-19 起）

牌效只回答「多快听牌」，打点回答「和了值多少」。两类判据分开写：

| 判据 | 触发条件 | 写法 |
|---|---|---|
| 宝牌 | 两种切法的宝牌张数不同 | 明说留了几张、白捡几番 |
| 断幺 | 一种成立、另一种不成立 | 「零代价白捡一番」 |
| 役牌 | 一种留下役牌对子/单张 | 点名是哪张、哪种役牌 |
| **通用番数** | 上面三条都不命中，但 `point_compare()` 算出 Mortal 那一手番更高 | 点名双方役种与成型番数/点数，差几番 |

`point_compare()` 对「打完这张后的 13 张」各跑一次 `yakucalc.outline()`，
所以混一色、清一色、七对子、对对和、平和、一气通贯、三色同顺、一杯口都能覆盖，
数字可复算。**打点不是永远优先**：向听差一手的页面只在末尾补一句打点对照，
不抢主判据——只有「牌效打平 / 打点差 1 番以上」时它才当 ①。

其中 **164 手（52%）带「攻防」页**（场上有人立直或副露），首行分布：
继续做牌 68 / 该守 45 / 继续进攻 27 / 谨慎推进 14 / 偏守 6 / 不用取舍 4。
其余 150 手是纯牌效局面，不出这一页。

### 理论口径

一律引用 `_V2_理论口径.md`（2026-10-28 版）的结论，四条硬修正写在 `explain.py` 顶部注释里：

- **R1 先制立直默认要立**：愚形立直和率约为默听七成，但打点翻倍、被追立仅 ~20%，局收支更高；
  改良张不到 4 种就该立。「默听往往更优」是 AllLast 保顺位的特例，不能当通则。
- **R2 筋**：三个来源排序不一致，两筋456 与筋28 差 <1pp，**只排序、不换算成铳率数字**。
- **R3 壁**只挡一组两面；晚巡 OC 是陷阱。
- **R4 间四间 / 里筋**：数据已否定极端说法，既不特别危险也不完全无效，禁止引用。

以及一条方法论：**Mortal 是「这一巡最优」，不是全局最优**（它不储备安牌、不跨局规划，无路可退时偏乐观），
所以**微差不算错**——这也是为什么门槛要自己定：门槛之上一律算恶手（分颜色看轻重），
门槛之下的微差干脆不入库，别让它抢注意力。

## 六、分步面板：一页一个思考点

解读不是一坨文字，而是**按思考顺序切成页**，翻一页看一步。切分在 `explain.steps_of()` 里做，
**文字一个字都不改**，只重组（所以改不出新错误，也不重算牌理）。

页序固定：**局面 → 关键点（几页取决于这一手用到哪些维度）→ 结论 → 候选评分**。

> 界面上不再翻到「候选评分」这一页：`cand` 页的数据照旧生成（`coach/*.json` 里的 `top`），
> 但前端 `renderCoach()` 会把它过滤掉，改由中间栏那块**常驻候选表**显示（见 `index.js` 的
> `weightTable()` / `paintWeight()`）——表格不受分页影响，翻到哪一页都在。

| 页 | 内容来源 | 标题怎么来 |
|---|---|---|
| 局面 | `场况：…` 那一行 | 固定「局面」，末尾加一句「往下看：下一站」当目录 |
| 攻防 | `攻守：…` 那一行 + 紧随的「威胁 / 本钱 / 退路」几行 | 「攻防 · 继续攻」或「攻防 · 该守」（页标「攻」或「守」） |
| 关键点 | 每个 `①②③` 各一页，含它下面的缩进续行和紧随的 `原理：` | 「大类 · 小标题」，如「牌效 · 浮牌价值」「防守 · 安全」 |
| 结论 | `结论：…` | 固定「结论」，并追加一句 `下次：…`（按标签查 `LESSON` 表，14 类各一句） |
| 候选评分 | `Mortal 评分：…` + `—— 参考：…` | 固定「候选评分」（界面上隐藏，数据给中间栏表格用） |

> 「攻防」页只在**场上有人立直或副露**时出现（`attack_defense()` 返回空列表就不占页）；
> 无人进攻时场况行已经写明「全场无人立直，也没有副露」，不必再多一页废话。

**大类由小标题里的关键词判定**（`STEP_CLASS`，顺序敏感，先具体后牌效）：

```
安全                → 防守（页标「守」，红）
打点/役牌/宝牌/断幺 → 打点（「攻」）
向听/进张/浮牌/听牌质量/牌型/改良 → 牌效（「攻」）
立直 / 鸣牌·副露     → 立直 / 鸣牌（「判」）
其余                → 判断
```

另外两个字段：

- `badge`：正文里的「（决定性）」「（改良）」被提出来做成角标，标题因此更短；
- `side`：`局 / 攻 / 守 / 判 / 结 / 评` 六个字符，面板用它给标题前的小方块和当前步骤圆点上色。

于是同一手在界面上是这样的（以「浮牌价值」为例，共 5 页）：

```
[1] 局 局面            场况… + 往下看：牌效 · 浮牌价值
[2] 攻 牌效 · 浮牌价值  ① … + 原理…
[3] 攻 牌效 · 将来性    ② … + 原理…
[4] 结 结论            结论… + 下次：孤张先切…
```

界面实际只有 4 个圆点；权重表固定在中间栏，不占页。

**面板交互**（`index.js` 的 `paintSteps()`）：

- 顶部一排数字圆点，可直接点某一步跳过去；已看过的变暗、当前的高亮；
- 标题行 = 小方块（攻/守/判…）+ 页名 + 角标；
- 底部「‹ 上一步　n / N　下一步 ›」，到头的按钮自动禁用；
- 键盘 `[` / `]` 翻页（方向键已被「走巡」占用，冲突所以没用）；
- 换到另一手时**自动回到第 1 页**（`COACH_STEP_KEY` 比对 `hand:ply`）；
- 不是恶手的一手只有「局面」一页，中间栏会写「这一巡和 Mortal 一致，没有需要比对的候选」。

## 六之二、局面页：先把「做牌的前提」讲清

牌效率只回答「哪张进张多」。同一副牌，进张 6 种 20 枚在
「断幺平和 2000 点」和「混一色 8000 点」两条路线下价值完全不同，
所以**在做任何取舍之前，必须先把这四件事摆出来**：

```
点数：我方 25300（2位） · 下家 21900（3位） · 对家 20300（4位） · 上家 32500（1位）
顺位：距 1 位（上家）7200 点，二位，4 番可反超一位。
手牌：听牌 · 面子 3 · 搭子 1 · 浮牌 1 · 门前
做牌：走「断幺九 + 平和」这条线，基本成形（成型后 2 番，约 2000 点）。切掉 9筒 即可。
```

**① 点数与顺位**（`yakucalc.score_lines`）

- 数据来自报告的 `scores`（四家绝对座次），按 `seat` 转成「我方 / 下家 / 对家 / 上家」，
  同点按起家顺序排名；
- 四家同点 → 直接判「平场」，不给顺位建议（开局说「一位很薄」是错的）；
- 差距反查番数用 30 符子家表：1番 1000 / 2番 2000 / 3番 3900 / 4番 7700 /
  5番 满贯 8000 / 6~7番 跳满 12000 / 8~10番 倍满 16000；
- `S4局` 追加终盘提醒（守住 / 最后机会）；
- **它只是提示，不改变 Mortal 的推荐** —— Mortal 按局收支打分，从不建模顺位
  （V2 §4 M1~M4）。所以这里写「你这个顺位需要多大打点」，而不是「所以该打哪张」。

**② 手牌形状**（`mjcalc.shanten` + `mjeval.analyze_struct`）

`1 向听 · 面子 1 · 搭子 4 · 浮牌 3` —— 三个数加起来正好 14 张
（面子×3 + 搭子×2 + 浮牌×1）。搭子含对子，因为 5-block 理论里对子也是一个 block。

**③ 役种走向**（`yakucalc.routes`）

把 10 条路线都算一遍「完成度」，再挑主线：

| 路线 | 完成度 | 番数（门前 / 副露） |
|---|---|---|
| 断幺九 | 非幺九张 ÷ 总张 | 1 / 1 |
| 混一色 | (主花色 + 字牌) ÷ 总张 | 3 / 2 |
| 清一色 | 主花色差一张以内 | 6 / 5 |
| 役牌（三元・自风・场风） | 对子 0.62、刻子 1.0 | 1 / 1 |
| 七对子 | 对子数 ÷ 7（4 张算两对） | 2 / 不可 |
| 对对和 | (刻子数 + 0.5) ÷ 4；**手里有顺子时压到 0.45 以下** | 2 / 2 |
| 平和 | 顺子组数 ÷ 4（须门前、无刻子） | +1 |
| 一气通贯 | 已有段数 ÷ 3 | +2 / +1 |
| 三色同顺 | 已有花色数 ÷ 3 | +2 / +1 |
| 一杯口 | 同色同顺两组 | +1 |

选主线的公式是 **完成度 × 该番数对应的点数**，不是单看完成度 ——
否则「断幺 1000 点」会压过「混一色 3900 点」。同组的路线互斥（只能选一条），
附加役（平和/一气/三色/一杯口）满足 0.72 就叠加上去。

阈值：牌型组（A 组）完成度 ≥0.55 才进候选，附加役（B 组）≥0.72 才叠加；
0.88 以上写「基本成形」，0.72~0.88 写「八成」，再低写「只是倾向，还要看进张」。

**为什么不当结论用**：Mortal 不按「役种目标」打分，它只算这一巡的期望。
所以局面页的做牌行是**给你理解 Mortal 的取舍用的** ——
比如它推荐打 9筒 而不是 8筒，往往就是因为 9筒 是断幺的障碍张。

**什么时候干脆不写**：已经听牌（或已和）时，牌型就固定了，再写「走 XX 这条线、八成」
就变成硬编。典型反例：`666m 345s 78s` 外加碰了 2p 和發 的听牌手，被写成
「走『对对和』这条线」——手里明摆着一组顺子，对对和根本不成形。现在改成
`shanten <= 0` 就不输出做牌行，只留「手牌」那行（它已经写明「听牌」）；

## 七、④ 坐标映射：让前端能查到

前端的状态变量是 `GS.hand_counter`（第几局，从 0 起）和 `GS.ply_counter`（该局内第几个事件），
与 `index.js` 的 `parseMortalJsonStr()` 完全同源。`build_positions(log)` 复刻同一套规则：

```
跳过 start_game / end_game / dora
遇到 start_kyoku → hand += 1, ply = 0
遇到 end_kyoku  → 不编号
其余每个事件 → 记 (hand, ply)，然后 ply += 1
```

于是 `bad_moves.json` 里每条记录都带 `kd_hand` / `kd_ply`，
前端 `renderCoach()` 在 `updateState()` 末尾用 `${hand}:${ply}` 去 `coach/<标签>.json` 查表。
查不到（不是恶手点）就退化成简报：「你打 X / Mortal 推荐 Y / 期望损失 −0.105」——**每一巡都有内容，不留白**。

## 八之二、界面层：全中文、三下拉、局巡导航

这一层不参与牌理计算，但决定"能不能用"。三件事都是纯前端 + 少量 Python，零 token。

### 1. 界面固定简体中文

回放器原本是 killerducky 的多语言壳（en / ja / ko / ru / zh-CN），但 `main()` 里默认语言取
`localStorage.lang || "en"`，而 `translations.js` 的 zh-CN 段又长期没被选中用 —— 所以一直是英文。

改法：

- `main()` 里写死 `lang = "zh-CN"` 并回写 localStorage（**不再读旧值**，否则上次存的 "en" 会一直生效）
- `i18next_data.fallbackLng` 从 `"en"` 改成 `"zh-CN"`，任何漏翻的 key 也落中文
- `index.html` 里按钮的初始文本、`placeholder`、`<title>` 全部直接写中文，
  避免加载瞬间闪一下英文（`connectUI()` 是异步补文本的）
- 两处 `alert("Invalid URL…")` 改成中文提示
- 侧栏按钮语义按本应用重命名：`Prev Error` → 「上一恶手」。恶手是我们自己的定义（权重差 ≥ 10pt 入库），
  不叫 "Error"

**一个必须一起改的冲突**：原壳把 `[` `]` 绑给「上一/下一局」，
而分步面板把 `[` `]` 用来「上一步/下一步」。两个监听器都挂在 `document` 上，
一次按键会同时触发 → 翻页的同时还换了局。修法是**把切局的快捷键收回 `Home` / `End`**
（`index.js` 的 keydown 分支），`[` `]` 专职翻解读页，「关于」里的键位表同步改掉。

### 2. 分析前的三个下拉

Mortal 官网表单（`https://mjai.ekyu.moe/` 的 `reviewForm`）本来就有这些字段，
以前 `submit_auto.mjs` 全写死成 `log-url / 4.0 / player-id=""`。现在拆成三个下拉：

| 界面 | 表单字段 | 取值 |
|---|---|---|
| 格式 | `input-method`（radio） | `log-url` / `riichi-city-log-id` / `hime-mahjong-log-id` / `tenhou6` |
| Mortal | `mortal-model-tag` | `4.1c` 进攻 / `4.1b` 均衡 / `4.1a` 防守 / `4.0` 旧版 / `3.0` 类人 |
| 座次 | `player-id` | `""` 自动，或 `0` 东起 … `3` 北起 |

**麻雀一番街 = Riichi City**，它的牌谱不是链接而是一个对局 ID（形如 `ch35u1e9nc70954ah9n0@3`），
末尾的 `@N` 就是座位。所以：

- `app/main.py::guess_format()` 按内容猜格式（`http` → 链接；`数字_24位hex` → 姬麻将；
  `{` 开头 → 天凤6；其余字母数字串 → 一番街），用户下拉选了就以下拉为准
- `seat_from_log_id()` 从 `@N` 取座位；**非链接形式的牌谱 Mortal 强制要座位**（表单会拦），
  取不到就直接返回中文错误让用户选，而不是提交一个必失败的表单
- `submit_auto.mjs` 收一个 JSON 配置（`{url, format, model, seat, kyokus}`），
  设 radio 后调页面自己的 `changeInputMethod()` 展开对应输入框，再逐字段赋值

**判定「报告出来了」用的是 URL 规则 + DOM 双条件**（`tools/url_rules.mjs`）：
只有 pathname 是 `/report`（或 `/report/…`），或 pathname 含 `killerducky` **且 data 非空**，才算报告页；
首页、`/progress`、`/review` 的纯文本错误页、非 `mjai.ekyu.moe` 主机一律不认。
在报告页上还要等 `.info-round` / `.grid-main` 出现（killerducky 牌桌独有节点）才真正开始下载。
旧写法「不是首页、不是 progress」会把没提交成功的首页当报告页，于是 Python 拿不到 `data`，
用户只看到一句「报告地址里没有数据参数」—— 现在每种失败都有独立的标记与中文说明。

**雀魂 UUID 链接必须选座次**：`?paipu=261117-8f8a…`（没有 `_a123456789` 那段）里没有玩家 ID，
Mortal 会回一行纯文本 `does not contain player ID…`。现在本地先拦：
直接提示「请在座次里选一个」，不浪费一次提交。

**干跑自检**：`MC_DRY=1` 或配置里 `dry:1` 时只填表不提交，打印一遍表单快照就退出。
换格式 / 换模型时先用它验字段映射，不会白白消耗 Mortal 配额（也不会踩 Turnstile）。

### 3. 局 / 巡导航：两个下拉（不是一堆按钮）

数据全部来自页面已有的 `GS.ge`（每局一个事件数组）与 `COACH.moves`（`"hand:ply"` 查表），
不新增任何后端字段：

```
buildNav()      每局算一个 per[ply] = 第几巡
                规则：自家 tsumo 计一次（e.actor === hero）；有 mortalEval.junme 时以它为准并校准计数
                同时记 jun[] = 该巡的第一个"我方决策点"ply，供跳转落点用
buildBadMarks() 遍历 COACH.moves 的 key，用 per[ply] 反查巡目
                → NAV_BAD[hand] = Map(巡目 → {sev, ply})，同巡多处恶手取更重的那一手
paintNav()      两个 <select>：局数、巡目；同步当前值，选项文字里直接标恶手
gotoJunme()     该巡有恶手就落到恶手那一手，否则落到该巡第一个决策点
```

界面长这样（局 / 巡各一个下拉，选项里带恶手标注）：

```
局数  [ 东1局 · 恶手 4 处        ▾ ]     ← 只写计数，不上色
巡目  [ 第 3 巡 · 严重          ▾ ]     ← 恶手巡按档位上色（红/橙/黄）
```

- 选局 → 直接落到**该局第一处恶手**；选巡 → 落到该巡，该巡有恶手就落到恶手那一手
- **只给巡目染色**：一局里 80% 的巡都可能是恶手，整局上色等于没有信息量
- 局名从 `fullData.split_logs[h].log[0][0]` 解：`floor(raw[0]/4)` 是风（东南西北），
  `raw[0]%4+1` 是局数，`raw[1]` 是本场 → 「东3-1」
- 面板标题栏同步显示「东1局 · 第3巡」，右边的徽章只说**损失程度**（如「损失 严重」）；
  类型、权重差、Q 值放在悬停提示里，不占版面——权重差本来就能在权重表里看到

（早期这里是一排局按钮 + 一排巡目数字，19 巡要占 4 行，侧栏被撑高；改下拉后同样的信息一屏放得下。）

顺带两个布局修正：`opt-info`（右侧那张「操作 / Q / P」明细表）与解读面板的候选评分重复，
桌面版收起以让出宽度；侧栏限高 + `overflow-y:auto`，否则内容多了会被挤出牌桌。

### 4. 提交后的状态反馈（不再「假成功」）

`submit_link()` 返回的不是 `ok: true/false` 两个值，而是带阶段的结果：

```json
{"ok": false, "status": "failed|partial|ok", "stage": "SEAT_REQUIRED|NO_TOKEN|…",
 "tag": "261117", "bad_moves": 16, "msg": "失败（阶段 …）：可以直接照做的中文说明"}
```

前端据此做三件事：

1. **提交期间禁用「分析」按钮**，并把状态条染成黄色（`busy`），避免连点两次覆盖同一标签
2. **成功也要验证**：先 `initLibrary()` 刷新局列表，再轮询 `coach/<标签>.json`（1 秒 × 10 次），
   拿到 `moves` 的第一条坐标才跳转；拿不到就明说「报告已下载，解读文件还没读到」而不是白屏
3. **失败要可操作**：`failed` 红色、`partial` 橙色，文案里带阶段名与 `library/logs/<标签>.log`；
   `no_bad_moves` 这种合法空结果显示「本局没有超过 10pt 阈值的恶手」，不能写成「解读失败」

`loadCoach()` 也不再吞异常：HTTP 状态与错误信息会写进侧栏状态条 + 控制台。

## 十、已知局限

1. **阈值语义**：`T=0.1` 下「差 10pt」的门槛已经很低，恶手清单偏长是刻意的——分级负责砍，入口负责全。
   真正的严重程度要看 Q 损分级，面板与 Excel 都已标出。
2. **Mortal 的短视**：它按这一巡的期望值打分，不储备安牌、不做跨局顺位调整。
   有些被判恶手的牌，从"保住安牌打点"的角度看未必错——解读里会用「Mortal 是这一巡最优」提醒。
3. **模板会重复**：同一类恶手看多了措辞相近，因为填的是同一套判据。
   想要"这一手怎么说都不重样"就得接大模型（那样一手约 2 万 token）。
4. **顺位只做提示**：局面页现在会写点数、顺位和「需要几番」，但**不会据此改写 Mortal 的推荐**
   （Mortal 本身不建模顺位）。真要按顺位调整打法，得自己在那句话上加减。
5. **役种走向是启发式**：`yakucalc` 只做「有没有这个形状」的判定，不解完整向听役种树；
   完成度 0.5~0.7 的路线只能当倾向看，别当成「一定能做成」。
6. **攻防页的边界**：`attack_defense()` 只量化「威胁 / 本钱 / 退路」三项，
   **不算和牌率与铳率的期望值**（那需要对手手牌分布，属于推测），也拿不到立直巡目
   （mjai 快照里 `riichi` 只有布尔值），只能用「牌河张数」近似该家的进度。
   所以它给的是「该不该打」的定性依据，不是精确的 EV 比较；顺位压力同样不进入攻守判断。
7. **制图依赖 Pillow**：解释器里没有 Pillow 时会自动跳过配图（`--no-img` 同理），文字部分不受影响。

## 十一、加一局的最短路径

```bat
:: 1) 把 Mortal 报告放进 library/report/（文件名就是标签，如 261119.json）
:: 2) 双击 一键重建解读.bat        → 自动挑出缺解读的局，逐局生成
:: 3) 双击 mortal-coach.exe            → 下拉里就有新局
```

或者直接粘链接到 App 里 —— 它会自己提交 Mortal、下载报告、跑完这条流水线，一次到位。
